## 3. Находки по приоритету

### 🔴 КРИТИЧНО (чинить в первую очередь)

**C1. Катастрофически тонкий контент.**
Внутренняя страница услуги «Организационный дизайн» = **~100 слов видимого текста** на 130 КБ HTML. Главная — набор плашек-услуг по одной строке. AI-системам и поисковикам нечего извлекать. Для цитирования в AI-ответах нужно 600–1500+ слов структурированного, экспертного текста на страницу.
→ *Влияет на: AI-цитируемость, E-E-A-T, ранжирование.*

**C2. Нет llms.txt + сервер обрывает соединение на неизвестных URL.**
Файла `/llms.txt` нет. Хуже — запрос несуществующих путей (`/llms.txt`, `/404-test/`) не отдаёт чистый `404`, а **рвёт соединение** (`Соединение неожиданно закрыто`). Часть AI-краулеров и валидаторов воспримет это как нестабильность.
→ *Влияет на: AI-видимость, краулинг.*

**C3. Опечатки в продакшене.**
- `техналогическая поддержка` → **технологическая** (плашка IT на главной)
- `Crated by Tadaimatech` → **Created** (футер)
- Футер `© 2023` — устарел на 3 года.
Опечатки напрямую бьют по E-E-A-T (экспертность/доверие) и считываются как сигнал заброшенности.

**C4. Контент не обновлялся с 2023 г.**
`article:modified_time = 2023-11-15`. Сигнал свежести почти нулевой. AI-системы и Google отдают предпочтение свежему/поддерживаемому контенту.

### 🟠 ВЫСОКИЙ приоритет

**H1. Нарушена иерархия заголовков.**
Внутренняя страница содержит **3 тега `<h1>`** (норма — ровно один). На главной H1 «Отраслевая экосистема будущего» идёт *после* H2 «HATTATSU GROUP» и H2 «Простые решения» — нелогичный порядок для парсинга.

**H2. Слабый бренд-граф (entity signals).**
В `sameAs` организации — **только VK**. Нет LinkedIn, YouTube, Telegram, Дзен, профилей в отраслевых каталогах, Wikipedia/Wikidata. По данным Ahrefs (дек-2025) упоминания бренда коррелируют с AI-цитированием в **3 раза** сильнее, чем ссылки. Сейчас сущность «HATTATSU GROUP» для AI почти не подтверждена.

**H3. Нет специализированной Schema-разметки.**
Присутствует только дефолтный граф Yoast (`Organization`, `WebSite`+`SearchAction`, `WebPage`, `BreadcrumbList`). Для консалтинга/услуг **отсутствуют**: `Service` (на каждой странице услуги), `FAQPage`, `Organization` с полным NAP/`contactPoint`, отзывы/`Review`. Это закрывает доступ к rich-результатам и снижает машинопонимание.

**H4. Нет кэширования + нет CDN → медленно и уязвимо к нагрузке.**
`Cache-Control: max-age=3` (3 секунды — фактически кэш отключён). Origin-nginx без CDN. Elementor отдаёт 130–158 КБ HTML. Core Web Vitals почти наверняка страдают на мобильных.

### 🟡 СРЕДНИЙ приоритет

**M1. Нет security-заголовков.** Отсутствуют `Strict-Transport-Security` (HSTS), `X-Content-Type-Options`, `Content-Security-Policy`. Не SEO напрямую, но сигнал «trust/безопасность» и риск.

**M2. WP REST API полностью открыт.** `/wp-json/` отдаёт 567 КБ — перечисление контента/пользователей, лишний поверхностный риск. Стоит ограничить.

**M3. 15 изображений с пустым `alt=""`.** Потеря image-SEO и доступности; AI-описание картинок невозможно.

**M4. Нет brotli-сжатия.** Есть только gzip. Brotli дал бы −15–20% к весу.

**M5. Тонкая мета-/контентная связность.** Заголовок внутренней страницы «Производство», а URL `organizaczionnyj-dizajn` и H-тексты — про «организационный дизайн». Несогласованность сущностей.

### 🟢 НИЗКИЙ приоритет / гигиена

- «Осиротевшая» страница `elementor-3684` в sitemap (черновик/тест в индексе).
- Транслитерированные URL (`organizaczionnyj-dizajn-i-inzhiniring`) — длинные, с `cz`. Не критично, но не идеальны.
- Не подтверждены 301-редиректы `http→https` и `www→non-www` (canonical-тег стоит — это страхует, но серверный 301 желателен).

## 4. GEO-специфика: почему сайт «невидим» для AI-поиска

AI-системы (ChatGPT, Perplexity, Gemini, Google AI Overviews, YandexGPT/Алиса) цитируют то, что:
1. **легко извлекается** — чёткие вопрос-ответ блоки, списки, определения;
2. **подтверждено сущностью** — бренд упоминается на сторонних авторитетных площадках;
3. **экспертно и свежо** — авторы, цифры, кейсы, даты.

Сейчас hattatsu.pro не даёт ни одного из трёх. Конкретно для исправления:

**G1. Добавить `/llms.txt`** (карта сайта для LLM). Минимальный шаблон:

> Отраслевая консалтинговая экосистема: организационный дизайн и инжиниринг,
> управление и развитие персонала, обучение (лицензия № Л035-01255-50/00616315),
> организация мероприятий, маркетинг, IT-разработка. Россия.

## Услуги
- [Организационный дизайн и инжиниринг](https://hattatsu.pro/organizaczionnyj-dizajn-i-inzhiniring/): построение производственных систем, оптимизация процессов
- [Управление человеческими ресурсами](https://hattatsu.pro/upravlenie-chelovecheskimi-resursami/): подбор, адаптация кадров
- [Адаптация и развитие персонала](https://hattatsu.pro/adaptacziya-i-razvitie-personala/): корпоративный университет, развитие навыков

**G2. Добавить FAQ-блоки + `FAQPage` schema** на каждую страницу услуги (3–5 реальных Q&A). Это самый прямой путь в AI-ответы и в Google «People Also Ask». Пример:

    }
  }]

**G3. `Service` schema** на каждой странице услуги (привязка к `Organization`, `areaServed`, `provider`).

**G4. Нарастить контент до 600–1200 слов** на страницу услуги: проблема → подход → этапы → результаты с цифрами → кейс → FAQ. Это одновременно решает C1 и кормит AI-системы.

**G5. Стратегия упоминаний бренда** (вне сайта, самый сильный GEO-рычаг для РФ-рынка):
- Профили: Telegram-канал, YouTube/RUTUBE, Дзен, LinkedIn, отраслевые каталоги (Россия).
- Подтвердить сущность: Яндекс.Бизнес, карточка организации, при возможности Wikidata.
- Гостевые материалы/упоминания на отраслевых площадках (производство, HR, стекольная отрасль).
- Все профили → прописать в `sameAs` организации.

**G6. РФ-платформы:** настроить **IndexNow** (Яндекс + Bing мгновенная индексация), Яндекс.Вебмастер, Яндекс.Бизнес. Для AI-ответов в РФ это весомее, чем кажется.
